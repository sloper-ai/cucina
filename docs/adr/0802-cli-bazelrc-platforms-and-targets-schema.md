# 0802 — `cucinactl bazelrc`: flag scope, platform labels and the targets schema

* Status: accepted (2026-10-02)

## Context
UC9 and R-XPLAT-2(d) need `cucinactl bazelrc` to print endpoint, TLS, helper, instance, platform and transfer flags, and
cross configurations that depend on `platforms/targets.json`, which the cross-platform agent has not published yet.

## Decision
* Every non-startup flag is emitted under `common` (or `common:<name>` with `--config-name`): `common` options a command does
  not support are ignored, and identical options across `build`/`test`/`query` avoid analysis-cache discards. Values with
  spaces, quotes or backslashes are single-quoted for Bazel's rc tokenizer (Windows paths).
* Platform labels come from a **targets catalog** (schema in docs/cli.md §Targets schema): `execPlatforms` (one Bazel exec
  platform per pool runner, with `pool`/`runner`) and `targets` (hermetic-llvm platform, allowed compile exec platforms in
  preference order, test twin or `null`, `abi`). Until `platforms/targets.json` exists, the embedded copy is the fixture
  `cli/cucinactl/data/targets.json`; switch the `include_str!` in `catalog.rs` when it lands. MSVC EULA flags (abi `msvc`) and
  the Windows test environment (Windows targets, non-Windows clients) are generated by code, not data.
* Workspaces without `@cucina_platforms` can print `platform()` targets with `--emit-build-file` and point the native flags at
  them with `--platforms-package`; cross configurations always need the module (hermetic-llvm constraints).
* The credential helper path defaults to the installed `cucina-credential-helper` (next to `cucinactl`, then `PATH`), else
  `%workspace%/tools/cucina-credential-helper` with a comment explaining how to install it.

## Consequences
The cross agent must publish `platforms/targets.json` in this schema (or tell the CLI owner what differs). Every emitted flag
is checked against Bazel 9.2's flag list by the property test.
