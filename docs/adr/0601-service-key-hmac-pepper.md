# 0601 — Service-account keys: 256-bit random secrets hashed with HMAC-SHA-256 and a pepper

* Status: accepted (2026-10-02)

## Context
R-AUTH-10 requires opaque, long-lived, hashed, instantly revocable service-account keys exchanged at the STS. The task
allowed argon2id or HMAC-SHA-256 with a server pepper. Slow password hashes exist to resist guessing low-entropy
secrets; these secrets are generated by Cucina.

## Decision
* Key format `cuc_sk_<id>_<secret>`: id 10 random bytes, secret 32 random bytes (≥ 256 bits), both lower-case base32 (no
  `_` inside, double-click selectable, greppable prefix for secret scanners).
* Stored value `HMAC-SHA-256(pepper, "cucina-service-key-v1\0" + id + "\0" + secret)`, compared in constant time after a
  lookup by id. The 32-byte pepper lives in the signing-key Secret, the records in `auth.serviceKeysSecret`, so a leak of
  the key store alone does not allow offline verification.
* Not argon2id: with 256-bit secrets brute force is infeasible either way, and a memory-hard hash per exchange would turn
  the STS into a CPU/memory amplification target (every exchange is unauthenticated until verified).

## Consequences
* Verification costs microseconds; revocation and last-use live in the same record (read per exchange from the API server).
* The pepper cannot be rotated in place (it would invalidate every key); rotate keys instead.
