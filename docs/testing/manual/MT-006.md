# MT-006: TUI feel

Snapshot tests prove four to six key screens render, and recorded flows prove the main journeys. They cannot tell you whether the TUI *feels* right: that it resizes gracefully,
works over SSH and tmux, honours colour settings and does not corrupt the terminal. A person tries it.

## Preconditions

- A build of `cucinactl` that includes the TUI (`cucinactl tui`), pointed at a deployment with a few pools and hosts and some live activity, or at the fake management server used by its tests.
- Terminals: Terminal.app and iTerm2 on macOS, Windows Terminal (PowerShell and a WSL shell), tmux inside an SSH session to a Linux machine, and a plain Linux console if available.
- A way to add network latency (for example the Network Link Conditioner) for the SSH case.
- Evidence rules: [`README.md`](README.md#evidence).

## Steps

1. [agent] Run the automated checks first so you can focus on feel: `bazelisk test //cli/... --test_tag_filters=tier-unit,tier-integration`.
2. [human] In each terminal start the TUI (`cucinactl tui`, or `cucinactl` with no arguments on a terminal). It renders the overview without stray characters; box drawing and symbols are correct; it refreshes within about two seconds.
3. [human] Navigate every view by keyboard (overview, pools and workers, hosts, operations, cost). A help overlay lists the keys. `q` quits and leaves the terminal as it was: cursor visible, no echo problems, normal screen restored.
4. [human] Resize live: drag the window, maximise and restore it, split and zoom a tmux pane. The layout reflows without a panic.
5. [human] Shrink to 80x24, 60x20 and 40x12. Small sizes show a clear "terminal too small" message instead of a corrupted screen; growing the window again restores the view.
6. [human] Colour: run with `NO_COLOR=1` (no colour), in a 16-colour terminal, and with `COLORTERM=truecolor`. Try a light and a dark theme. Selection and alerts stay readable in all of them.
7. [human] Keys over tmux and SSH: arrows, Page Up and Page Down, Home and End, Tab and Shift-Tab, Esc (no long delay), function keys, and Ctrl-C.
8. [human] Add 200 ms of latency to the SSH link. The TUI stays usable and does not redraw the whole screen on every tick.
9. [human] Mouse: clicking a row selects it, the scroll wheel scrolls, and holding Shift still lets you select text in the terminal. Everything also works without the mouse.
10. [human] Every destructive action (drain, kill, revoke, re-image) asks for confirmation that names the target, and Esc cancels it.
11. [human] Cut the network while the TUI runs. It shows a disconnected or reconnecting state instead of crashing, and recovers when the network returns.
12. [human] Locale and width: with `LANG=C` borders fall back to ASCII; names with wide characters do not break column alignment.

## Expected results

- The TUI works in every listed terminal, over SSH and in tmux, and always leaves the terminal in a usable state.
- Resizing, tiny sizes, colour modes and key handling behave as described.
- Destructive actions cannot be triggered by accident.

## Required evidence

- A table of terminals by area (render, resize, small sizes, colour, keys, mouse), each marked ok or with an issue link.
- Screenshots or short recordings, at least one per terminal.
- Each defect as an issue. A defect that can be captured as a snapshot or a recorded flow becomes a regression test.
