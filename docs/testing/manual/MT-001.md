# MT-001: Mac mini enrollment through Apple Business, from a brand-new device

Proves that a brand-new Mac mini becomes a schedulable Cucina host with no hands-on steps beyond power, network and Setup Assistant, **including the path that
cannot be exercised anywhere else**: `cucina-hostd` running as a root LaunchDaemon and starting `tart` as the dedicated `cucina` user. The dev Mac runs hostd in
user mode, and macOS VMs cannot nest, so only a real host covers it.

## Preconditions

- A brand-new or factory-reset Apple-silicon Mac mini assigned to the MDM service in Apple Business, wired Ethernet, power. Note its serial number.
- A Cucina deployment whose client, worker and host endpoints the Mac can reach, the Cucina CA bundle, and an admin session (`cucinactl login`).
- A site enrollment token: `cucinactl hosts enroll-token create --site <site> --ttl 24h --max-hosts 1`. Keep the token in a password manager, never in a transcript.
- The signed host package published at an HTTPS URL, and the profiles from `macos/profiles` rendered for this deployment and uploaded to the MDM in the order given in
  [`docs/macos/mac-mini-setup.md`](../../macos/mac-mini-setup.md) (trust certificates first, then preferences and settings, then the package).
- A macOS pool for the golden image exists (`cucinactl pools list`), and a small Bazel project can build with the macOS execution platform from a Mac client.
- Evidence rules: [`README.md`](README.md#evidence). Redact serial numbers, addresses and tokens.

## Steps

1. [agent] Pre-register the serial so that no manual approval is needed: `cucinactl hosts register --site <site> <serial>`.
2. [human] Power the Mac on with Ethernet connected and do not touch it. Watch Setup Assistant: it should advance by itself. Note any pane that waits for input (a defect) and photograph it.
3. [human] Wait for the desktop. The `cucina` user must be logged in without input. Record the elapsed time from power-on.
4. [agent] On the Mac (SSH or the MDM's remote tool): `sudo profiles status -type enrollment` reports enrollment via the automated device enrollment and an MDM enrollment.
5. [agent] `sudo profiles list` shows the trust, preferences, login-items, energy, FileVault-prevention and firewall profiles (there is no auto-login profile unless your MDM creates the account: the package sets up auto-login itself). Confirm from the MDM's install log that the trust profile landed before the package.
6. [agent] The package is installed and its signature is trusted without `-allowUntrusted`: `pkgutil --pkgs | grep ai.sloper.cucina.host` and `pkgutil --pkg-info ai.sloper.cucina.host`.
7. [agent] The daemon is running and started at boot, not at login: `sudo launchctl print system/ai.sloper.cucina.hostd | head -20`, and compare `ps -o lstart= -p "$(pgrep -x cucina-hostd)"` with `who -b` and the `cucina` login time (`last -1 cucina`).
8. [agent] The login item is allowed: `sudo sfltool dumpbtm | grep -B2 -A8 ai.sloper.cucina.hostd` lists the daemon as enabled.
9. [agent] Host settings took effect: `fdesetup status` says FileVault is Off; `pmset -g | grep -E 'sleep|womp|autorestart'` shows sleep 0, womp 1, autorestart 1; `sudo systemsetup -getrestartfreeze` is On; `sudo /usr/local/cucina/bin/cucina-host-setup status` reports the daemon, the `cucina` user, auto-login and power settings (it prints no secrets).
10. [human] Reboot (`sudo shutdown -r now`). The Mac logs in as `cucina` by itself (`stat -f%Su /dev/console` prints `cucina`) and the host returns. Record the time to `Online`.
11. [agent] The host shows up and becomes schedulable: `cucinactl hosts list` (Pending until it connects and enrolls, then Online; there is no separate approved phase); if you skipped step 1 it stays `Pending (pending approval)` until `cucinactl hosts approve <serial>`.
12. [agent] The managed preferences were read and the token never leaked: the hostd log (`sudo log show --predicate 'subsystem == "ai.sloper.cucina"' --last 20m`, and the files under `/Library/Logs/Cucina/`) shows the configuration loaded, and searching it for the token returns nothing.
13. [agent] The image is pre-pulled: `cucinactl hosts list` and `tart list` on the Mac show the golden image.
14. [agent] Run a small macOS build from a Mac client with the pool at zero. A VM must start on demand.
15. [agent] **The root-daemon to `cucina`-user path**: while the VM runs, `ps -axo user,pid,command | grep '[t]art run'` on the Mac shows the user `cucina`, not root, and the log has no keychain error (`SecKeyCreateRandomKey_ios failed`). `cucinactl workers list --pool <macos pool>` shows the worker as `<serial>/<vm>`.
16. [human] No Local Network permission dialog appears on the Mac's screen at any point.
17. [agent] The build succeeds and its actions ran on the VM (`cucinactl ops list --stage completed --platform OSFamily=macos` or the build's execution log).
18. [agent] Token behaviour: `cucinactl hosts enroll-token list` shows `used_hosts` 1; revoke it with `cucinactl hosts enroll-token revoke <id>`; the enrolled host stays Online.
19. [human] Pull the power cable, then restore it. The host returns without hands-on (this overlaps MT-004; here only note whether it did).
20. [agent] Clean up: `cucinactl hosts drain <serial>`, wait for zero VMs, `cucinactl hosts remove <serial>`, then decommission the device through the MDM or run the uninstall script (`sudo /usr/local/cucina/bin/cucina-host-uninstall --purge --yes`) as described in the setup guide. Removal deny-lists the host's identity until its certificate would have expired plus an hour (up to seven days): to run this check again on the same Mac inside that window, expect its cache upstream to be refused, or use another Mac.

## Expected results

- No step needs hands-on work beyond power, network and Setup Assistant (steps 2 and 3).
- Profiles install in the documented order, the package installs without `-allowUntrusted`, and the daemon runs from boot.
- FileVault is Off, the energy settings and auto-login hold across a reboot, the login item is allowed.
- The host is admitted by serial number (pre-registered or approved) and reaches Online.
- `tart` runs as `cucina`, not as root; VMs start and their workers register through hostd.
- The token is never in a log. Revoking it does not affect the enrolled host.

## Required evidence

- Transcripts of steps 4 to 9, 11, 12, 15 and 17, with serial numbers, addresses and the token redacted.
- The elapsed times from steps 3, 10 and 14.
- A photograph or screenshot of Setup Assistant at its first screen and after auto-advance (steps 2 and 3).
- The MDM's install log showing the profile and package order.
- Defects found, each as an issue (a defect that can be automated becomes a regression test).
